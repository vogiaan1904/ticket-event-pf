# Decision records

A design says how the platform should work. A plan says what was done on a day.
Neither says **who decided, and why they chose this over the alternative** — and
that is the part a reader cannot reconstruct from the code.

One file per decision, `NNNN-<slug>.md`, numbered in the order they were made.
Numbers are never reused and a superseded record is never deleted: it gains a
`Superseded by` line and stays, because the reasoning that was replaced is
itself evidence.

## Format

```markdown
# NNNN — <the decision, as a statement>

**Date:** YYYY-MM-DD
**Status:** proposed | accepted | superseded by [NNNN](NNNN-<slug>.md)
**Arc:** <arc-slug> — <the plan or design it came from>
**Where it lives:** `path/to/file.go:123`

| Question | Chose | Instead of | Cost |
|---|---|---|---|
| <the question it answers> | <the option taken> | <the best option not taken> | <what the choice gives up> |

## Context
The forces. What was true that made this a question at all.

## Options
Each one that was genuinely on the table, with what it costs.

## Decision
The call — see the one rule below.

## Consequences
What this makes easy, what it makes hard, and what has to be true for it to
keep holding.

## Outcome
Added on acceptance: what happened when it landed — commits, tests, a run.
```

The review row is the record's one-line summary and its only home: the index at
the bottom of this file is generated from it. `Where it lives` may be omitted
for a decision with no code.

## Lifecycle

- **proposed** — written in the same change as the call, while the reasoning is
  still in the room.
- **accepted** — the work landed. The record gains an Outcome citing the evidence,
  and from then on changes only to gain a `superseded by` pointer.
- **superseded** — a later record replaced it. It stays, and stays in the index.

The agent drafts records as calls are made, through the `decision-records` skill;
[0011](0011-decisions-are-recorded-when-made.md) says why nothing here is a gate.

## The one rule that matters

**A Decision section never paraphrases the decider.** It does one of three things:

- quotes the decider's own words;
- records a delegation as one — `Delegated: "<their words>"` — so a review shows
  which calls were made and which were handed over;
- says the decision was reconstructed after the fact, and from what.

A record that paraphrases is a record of the paraphraser's reasoning, which is the
thing this folder exists to avoid.

## What earns a record

A choice a competent engineer could have made differently, whose consequences
outlive the session that made it: a schema, a contract, a deploy topology, the
shape of CI, what is allowed on `main`.

Tactical calls do not: which flag to pass, how to name a local variable. Those
get surfaced in conversation and left there.
