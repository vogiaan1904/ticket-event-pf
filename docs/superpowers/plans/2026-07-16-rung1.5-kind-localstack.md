# Rung 1.5 — kind + LocalStack (AWS services only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the existing kind cluster, swap only the AWS-native pieces to a host-side LocalStack — order's datastore → **LocalStack DynamoDB**, and the payment async path → the real **Lambdas** (`payment-webhook-handler` via API Gateway, `outbox-processor` via EventBridge) — delivered as a `values-localstack.yaml` overlay, verified end-to-end by Gate 1.5.

**Architecture:** kind keeps running all 8 apps + Redpanda + Temporal + Postgres + Redis unchanged. A host-side **LocalStack Pro (student token)** container on the **`kind` docker network** provides DynamoDB + Lambda + API Gateway + EventBridge. Three cross-boundary hops: order-svc → LocalStack DynamoDB (k8s Service/Endpoints to LocalStack's static IP); the two Lambdas → payment-Postgres + Redpanda in kind (NodePorts). No kind recreate needed — LocalStack's Lambdas join the `kind` network and reach the node.

**Tech Stack:** Helm (existing chart `deploy/helm/ticketbottle`), kind, LocalStack Pro, AWS Lambda (nodejs20.x), API Gateway, EventBridge, `awslocal`, Redpanda multi-listener, kubectl, bash + python3.

**Design spec:** `docs/superpowers/specs/2026-07-15-localstack-rung-design.md`

## Global Constraints

- **Base is the kind cluster + existing Helm chart.** Do NOT re-host kind's infra (Redpanda/Temporal/Postgres/Redis) in Compose. LocalStack provides ONLY DynamoDB, Lambda, API Gateway, EventBridge, IAM, STS, Logs.
- **LocalStack = host-side container** on the `kind` docker network, `LAMBDA_DOCKER_NETWORK=kind`, publishes `4566` to the host. **LocalStack Pro (student token)** is the default edition; token is `LOCALSTACK_AUTH_TOKEN` in `development/envs/.env.localstack`. Verify `edition=pro` before deploying Lambdas.
- **Delivered as an overlay:** `helm ... -f values-local.yaml -f values-localstack.yaml`. Plain kind mode (`-f values-local.yaml` only: DynamoDB-local + `payment-events` adapter, Gate 1) stays the default and must keep working.
- **ZaloPay webhook signature:** `mac = HMAC_SHA256(<data JSON string>, ZALOPAY_KEY2)` with `ZALOPAY_KEY2` read from `services/payment-svc/lambdas/envs/env.localstack.json`; `type = 1`; `app_trans_id = "<YYMMDD>_<ORDER_CODE>"`; order codes contain no underscores.
- **Node runtime:** functions target `nodejs20.x`. Lambda zips already rebuilt with the `rhel-openssl-3.0.x` Prisma engine (git-ignored `services/payment-svc/lambdas/build/`).
- **Verification is behavioural** — Gate 1.5 (the end-to-end purchase flow). No unit tests.
- **Namespace** `ticketbottle`, Helm release `tb`, kube context `kind-ticketbottle`, kind node container `ticketbottle-control-plane`.
- **Branch:** `feat/rung1.5-localstack`.

### Task B5: LocalStack bridge — Service/Endpoints + payment-Postgres NodePort

**Files:**

When enabled, renders: (a) a headless `localstack` Service + an `Endpoints` object pointing at `localstack.ip:4566` (so kind pods reach LocalStack by cluster DNS), and (b) a `postgres-ext` NodePort Service (nodePort→5432) so the Lambdas reach payment-Postgres.

- [ ] **Step 1: Add defaults**

In `values.yaml`:
```yaml

  expose: false
  ip: 172.18.0.100
  postgresNodePort: 31432
```

- [ ] **Step 2: Create the template**

`deploy/helm/ticketbottle/templates/infra/localstack-bridge.yaml`:
```yaml
{{- if .Values.localstack.expose }}
# Lets kind pods reach the host-side LocalStack (on the `kind` docker net) by
# cluster DNS: order-svc uses http://localstack.{{ include "tb.namespace" . }}.svc:4566
apiVersion: v1
kind: Service
metadata:
  name: localstack
  namespace: {{ include "tb.namespace" . }}
  labels: {{- include "tb.labels" . | nindent 4 }}
spec:
  ports:
    - { name: gateway, port: 4566, targetPort: 4566 }
---
apiVersion: v1
kind: Endpoints
metadata:
  name: localstack
  namespace: {{ include "tb.namespace" . }}
  labels: {{- include "tb.labels" . | nindent 4 }}
subsets:
  - addresses:
      - { ip: {{ .Values.localstack.ip | quote }} }
    ports:
      - { name: gateway, port: 4566 }
---
# Exposes payment-Postgres to the LocalStack Lambdas (on the `kind` docker net)
apiVersion: v1
kind: Service
metadata:
  name: postgres-ext
  namespace: {{ include "tb.namespace" . }}
  labels: {{- include "tb.labels" . | nindent 4 }}
spec:
  type: NodePort
  selector: { app: postgres }
  ports:
    - name: postgres-ext
      port: 5432
      targetPort: 5432
      nodePort: {{ .Values.localstack.postgresNodePort }}
{{- end }}
```

> Note: the `Endpoints` name matches the `Service` name (`localstack`) so it binds — this is the manual-endpoints pattern for a service with no selector.
